# 问答三档评价

## 使用方式

开启原有 AI 问答反馈设置后，新生成的回答下方显示“已解决、部分解决、未解决”。适用于网页问答、嵌入窗口和手机问答页。

- 已解决：直接提交。
- 部分解决、未解决：打开原因弹窗，可选一项原因及填写最多 200 字说明，也可跳过原因直接提交。
- 取消或关闭弹窗：不提交评价。
- 提交失败：保留输入内容，允许重试。
- 沿用原有每条回答只能评价一次的规则，多轮对话分别评价各轮回答。
- 沿用原有历史会话展示规则：刷新加载的历史消息不显示评价入口（历史接口尚未返回消息 ID 和评价）。

后台“反馈 → AI 问答评价”显示三档结果，悬停查看原因和补充说明。

## 数据兼容

复用 `/share/v1/chat/feedback`，按 `message_id` 保存至现有消息 `info` 字段，无需数据库迁移。

| score | 含义 |
| --- | --- |
| 0 | 未评价 |
| 1 / -1 | 原有点赞 / 点踩，不等同于解决率评价 |
| 2 | 部分解决 |
| 3 | 已解决 |
| 4 | 未解决 |

原因复用 `type`，说明复用 `feedback_content`。本次不新增准确率、解决率统计或人工评审。

## 部署与验收

需要更新 `api`、`app`、`admin` 三个模块。合并并拉取代码后，在服务器仓库根目录执行 `sudo ./scripts/pwctl.sh update api,app,admin`。

上线前在测试环境检查：

1. 新建多轮对话，分别提交三种评价；后台应显示对应问题与结果。
2. 原因不填、只选原因、只填说明、同时填写均可提交；“其他”不强制填写说明。
3. 关闭弹窗不产生记录；重复点击提交不产生多次请求。
4. 模拟请求失败，弹窗保留输入，按钮恢复可用，重试成功后关闭弹窗。
5. 确认原点赞、点踩仍按历史评价展示，新的文字原因可查看。
6. 手机窄屏下按钮可以换行；关闭反馈设置后不显示评价入口。
